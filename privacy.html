Safety and privacy

Privacy policy

Two separate things share this name, so this page covers both: what this documentation website collects, and what the AppInspect library does with data on a device. Neither sends anything to us.

Last updated: 21 August 2026

This website

No cookies are set. There are no accounts, no sign-up forms, no login, no advertising pixels, no session recording, no heatmaps, and no contact form that submits personal data.

Three third-party resources are loaded, and it is worth being specific about each:

Cloudflare Web Analytics
A cookie-free beacon (static.cloudflareinsights.com/beacon.min.js) counts page views and measures performance. It sets no cookies, does not track individuals across sites, and does not fingerprint visitors. Only aggregate data — page views, countries, referrers — is visible, and only to the site owner.
Google Fonts
Manrope and JetBrains Mono are loaded from fonts.googleapis.com. Google may log the request IP and user agent under its own privacy policy.
Outbound links
Links to Maven Central, GitHub and LinkedIn go to sites with their own privacy policies, which may set cookies on their own domains.

Your theme choice is stored in localStorage in your browser. It never leaves the device and is not readable by anyone else.

The library

AppInspect is a developer tool that runs inside a host Android application. It has no cloud backend, requires no account, and never uploads anything to any AppInspect-operated service — because there is no such service.

What it never does

  • Require an AppInspect account or registration.
  • Upload captured network events, crash reports or storage data anywhere.
  • Send usage or crash telemetry about the inspector itself.
  • Include advertising SDKs or tracking libraries.
  • Alter the requests your app sends. Response mocking changes only what your app receives back, entirely on the device — the matching conditions in a rule are filters, never transmitted data.

What it stores on the device

  • Captured OkHttp requests and responses, in an app-private SQLite database (appinspect_storage.db), subject to a retention cap.
  • Uncaught exceptions, and on Android 11+ ANR and native crash records, in the same private database — up to 50 recent events.
  • Storage and WorkManager data is read from the host app on demand and is never copied or persisted by AppInspect.
  • Mock rules created in the inspector, in the same private database. A mirror copy is also written to Android/data/<your.package>/files/appinspect/mocks.json — app-scoped external storage, so the file can be retrieved with adb pull — and only on builds where mocking is allowed. Rules are developer-authored configuration and are stored exactly as written, so real credentials should never be placed in a mock response body.
  • EncryptedSharedPreferences files are decrypted for read-only viewing using the host app's own on-device Keystore key. Decryption never leaves the device, and encrypted files can never be edited or deleted from the inspector.
  • All of it is private to the host app and inaccessible to other apps without root.
  • It is deleted when someone taps Clear inside the inspector, or when the host app is uninstalled.

Exports

The library can write network logs as TXT or HAR, mock rules as JSON, and crash reports for the Android share sheet. These files are created only when a person taps the export or share action, are written to cacheDir/appinspect_exports/, and are shared through a FileProvider that cannot grant access to any other path. Nothing is sent automatically.

Exports can contain sensitive data

A network export includes full request and response headers — which means authorization tokens, API keys and session cookies, including credentials attached downstream of AppInspect — plus body content up to the capture limit. They are intended for internal debugging. Redact credentials before sharing one outside your team; the QA checklist explains how.

Production builds

With appinspect-no-op in your release variant, none of the above applies to your users: there is no inspector, no database and no capture code in the APK. Even if the full library ships by mistake, it detects the non-debuggable build and disables itself. The full security model →
